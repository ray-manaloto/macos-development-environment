The RTK hook is wired as:
```

```

This is a hardcoded absolute path with a specific username. Any other developer who clones this repo and runs `chezmoi apply` will get a `settings.json` that invokes a path that does not exist on their machine. 3. Use a project-relative wrapper: `uv run mde-py hooks rtk-rewrite` following the hooks-auto-discovery pattern — this also resolves the policy violation (Finding 3 below).

### FINDING 2 — P1 CRITICAL: `|| true` silently swallows RTK init failures

**File:** `.chezmoisource/.chezmoiscripts/run_onchange_after_install_mise.sh.tmpl` lines 22–23

```bash
rtk init -g 2>/dev/null || true
```

The feedback memory `feedback_enforcement_policy.md` states: **"Never use `|| true` in CI; never classify failures as pre-existing without user approval."** The `2>/dev/null` additionally hides all stderr. If `rtk init -g` fails (e.g., permission denied creating `~/.claude/hooks/`, disk full, binary corrupt), the chezmoi script will exit 0 and the user will have no indication that the hook was never installed. The hook entry in `settings.json` will then reference a non-existent file, silently breaking RTK for every Bash call.

The comment says "Idempotent — safe to re-run" to justify the suppression, but idempotency does not justify hiding errors on the initial run.

**Fix:** Remove `2>/dev/null`. If the intent is to tolerate "already initialized" as non-error, check the exit code explicitly or test for the hook file's existence before calling init.

### FINDING 4 — P2 IMPORTANT: `CLAUDE_PLUGIN_DATA` tilde may not expand

**File:** `.claude/settings.json` line 18

```json
"CLAUDE_PLUGIN_DATA": "~/.claude-octopus"
```

The `env` block in `settings.json` is consumed by the Claude Code process, not by a shell. Tilde (`~`) is a shell-ism — it is **not** a standard environment variable expansion. Whether Claude Code expands it depends on its internal implementation. If it does not, `CLAUDE_PLUGIN_DATA` will literally be the string `~/.claude-octopus`, and the octo plugin (which uses `${CLAUDE_PLUGIN_DATA:-~/.claude-octopus}` as a fallback) will attempt to create a directory named `~` in the current working directory.

The octo changelog confirms the expected value is `~/.claude-octopus/` expanded, and the plugin code contains `"${CLAUDE_PLUGIN_DATA:-~/.claude-octopus/}"` — meaning if `CLAUDE_PLUGIN_DATA` is set to the literal string `~/.claude-octopus`, the fallback never triggers and the plugin uses the unexpanded path.

**Fix:** Use an absolute path: `"/Users/rmanaloto/.claude-octopus"`. If portability matters, move this to a chezmoi template for `settings.json` (if that exists) or accept the hardcoded path.
