## Official Claude Code Skills Conventions

### Directory Structure

The correct directory for custom skills is **`.claude/skills/`** at the project level:

```
.claude/skills/<skill-name>/SKILL.md
```

Skills can live at three levels (in priority order):
1. **Enterprise**: Configured via managed settings (all users in organization)
2. **Personal**: `~/.claude/skills/<skill-name>/SKILL.md` (all your projects)
3. **Project**: `.claude/skills/<skill-name>/SKILL.md` (this project only)

Plugin skills use the pattern: `<plugin>/skills/<skill-name>/SKILL.md`

**Note:** The old `.claude/commands/` directory still works for backwards compatibility, but `.claude/skills/` is now the recommended approach.

### Filename Convention

The entry point file MUST be named **`SKILL.md`** (exactly, case-sensitive).

Skills can optionally have supporting files in the same directory:
```
my-skill/
├── SKILL.md           # Required main file
├── reference.md       # Optional detailed docs
├── examples.md        # Optional examples
└── scripts/
    └── helper.py      # Optional utilities
```

### Frontmatter Fields (YAML)

All frontmatter fields are optional. The supported fields are:

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Display name for the skill (lowercase, hyphens, max 64 chars). Uses directory name if omitted. |
| `description` | string | **Recommended.** What the skill does and when to use it. Claude uses this to decide when to load it automatically. |
| `argument-hint` | string | Hint for autocomplete showing expected arguments (e.g., `[issue-number]`) |
| `disable-model-invocation` | boolean | Set `true` to prevent Claude from auto-loading. Use for manual-only workflows like `/deploy` |
| `user-invocable` | boolean | Set `false` to hide from `/` menu. Use for background knowledge Claude should know but users shouldn't invoke directly |
| `allowed-tools` | string | Tools Claude can use without asking permission when this skill is active (e.g., `Read, Grep, Glob`) |
| `model` | string | Which model to use when this skill is active |
| `effort` | string | Effort level: `low`, `medium`, `high`, `max` (Opus 4.6 only) |
| `context` | string | Set to `fork` to run in isolated subagent context |
| `agent` | string | Subagent type to use with `context: fork` (e.g., `Explore`, `Plan`, `general-purpose`) |
| `hooks` | object | Hooks scoped to this skill's lifecycle |

### Dynamic Variable Substitutions

Within skill content (not frontmatter), you can use:

- `$ARGUMENTS` — All arguments passed when invoking the skill
- `$ARGUMENTS[N]` or `$N` — Specific argument by 0-based index
- `${CLAUDE_SESSION_ID}` — Current session ID
- `${CLAUDE_SKILL_DIR}` — Directory containing the skill's `SKILL.md`

### Minimal Example

```yaml
---
name: explain-code
description: Explains code with visual diagrams and analogies. Use when explaining how code works.
---

When explaining code:

1. Start with an analogy
2. Draw a diagram with ASCII art
3. Walk through step-by-step
4. Highlight a gotcha or common mistake
```

### Key Distinctions

- **`.claude/skills/` vs `.agents/skills/`**: Only `.claude/skills/` is officially supported. The `.agents/` directory is for subagent definitions (`.claude/agents/`), not skills.
- **`SKILL.md` vs other names**: Must be exactly `SKILL.md`, not `skill.md`, `Skill.md`, or other variations.
- **Frontmatter**: YAML between `---` markers at the top, containing configuration. All fields are optional.
