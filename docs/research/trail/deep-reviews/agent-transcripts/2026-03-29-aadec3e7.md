Key findings:

**Q1 — Ruff duplication: intentional.** hk fixers use `--fix` and format-in-place (auto-correct staged files). Quality gate uses `ruff check` and `ruff format --check` (verify-only). The sequence is fix-then-confirm, which is correct. Running both is by design.

**Q2 — What hk provides that quality gate doesn't:**
- `typos` — spell checker over staged files only (not in quality.py at all)
- `yamllint` — YAML linting via hk builtin (quality gate has its own `validate_yaml_files` but it's a different tool)
- `shellcheck` with auto-fix in `hk fix` mode
- `hk fix` hook — standalone auto-fixer runnable outside commit context
- Staged-file scoping — hk only checks files in the git index, not the full tree

**Q3 — What quality gate provides that hk doesn't:**
- `ty` type checker (hk has `Builtins.ty` but it's not in `hk.pkl`)
- `pyright` (no hk builtin at all)
- `pytest` (no hk builtin at all)
- `mde-validate` — 14 validator modules (mise, chezmoi, brew, docker, plugins, skills, memory, structural, etc.)

**Q4 — Unused hk features:** profiles, groups, `parallel: true`, stash modes (`"git"` and `"patch"` vs current `"none"`), `Builtins.ty`, `Builtins.pytest`, and per-step file-pattern matchers beyond the `.agents/skills/**` exclude already in place.

**Q5 — Should we consolidate?** No. The separation is load-bearing. hk = fast staged-file auto-fix + gate trigger (must be fast, runs on every commit). Quality gate = comprehensive repo-wide checks (ty, pyright, pytest, 14 validators) that would be too slow for pre-commit. The only genuine gap: `typos` and `yamllint` from hk are not re-run by `mde-py quality`, so a direct `mde-py quality` invocation skips them. That is a known trade-off, not a defect.

**Other hook systems:** No `.pre-commit-config.yaml`, no `lefthook.yml`, no `.husky/` at the project root. The `.git/hooks/pre-commit` is a single line delegating entirely to `mise x -- hk run pre-commit`. hk is the only pre-commit hook system in use.
