## Prompt-Type Hooks in Claude Code

Based on the official Claude Code documentation, here are the answers to your questions:

### 1. Expected Response Format

Prompt hooks expect Claude to return **JSON with a `decision` field**:

```json
{
  "decision": "yes"
}
```

or

```json
{
  "decision": "no"
}
```

Claude Code interprets:
- **`"yes"`** — allows/approves the action (equivalent to exit code 0 for command hooks)
- **`"no"`** — blocks/denies the action (equivalent to exit code 2 for command hooks)

### 2. What "JSON validation failed" Means

The "JSON validation failed" error occurs when Claude Code cannot parse the JSON response from the LLM. Common causes:

- **Shell profile interference**: If your `~/.zshrc` or `~/.bashrc` contains unconditional `echo` statements, that output gets prepended to the hook's JSON output, breaking parsing:
  ```
  Shell ready on arm64
  {"decision": "block", "reason": "Not allowed"}  # Invalid JSON
  ```
  
  **Fix**: Wrap echo statements to only run in interactive shells:
  ```bash
  if [[ $- == *i* ]]; then
    echo "Shell ready"
  fi
  ```

- For Stop hooks specifically, if your script doesn't check the `stop_hook_active` field, it can trigger an infinite loop where the hook keeps returning invalid JSON.

### 3. Output Format Control

You **cannot** directly control the output format—Claude Code expects only the `decision` field. However, you can provide context through the `prompt` field itself:

```json
{
  "type": "prompt",
  "prompt": "Should this command be allowed? Command: $ARGUMENTS. Only respond with {\"decision\": \"yes\"} or {\"decision\": \"no\"}."
}
```

The `$ARGUMENTS` placeholder is replaced with the complete JSON hook input, allowing you to reference specific fields like `$ARGUMENTS.tool_input.command`.

### 4. JSON Structure Claude Code Expects

The complete response schema is simple:

```json
{
  "decision": "yes" | "no"
}
```

For Stop hooks with prompt type, you can optionally include a `reason` field (though the documentation shows this for agent hooks):

```json
{
  "decision": "no",
  "reason": "explanation of why the action should be blocked"
}
```

### Configuration Example

Here's a complete Stop hook with type "prompt":

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Check if all requested tasks are complete. If yes, respond with {\"decision\": \"yes\"}. If no, respond with {\"decision\": \"no\"}.",
            "model": "opus",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

**Key difference from command hooks**: Prompt hooks don't use exit codes. They only rely on the JSON response—exit codes are ignored. The hook timeout is configurable (defaults to a fast model, typically Haiku, unless you specify `model: "opus"`).
