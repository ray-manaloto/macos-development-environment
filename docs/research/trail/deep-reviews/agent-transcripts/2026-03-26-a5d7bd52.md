## Architecture Decision: Do NOT migrate observability to devcontainer

After researching the devcontainer spec (`dockerComposeFile`, `runServices`, `service`, `shutdownAction`) via context7, I determined that **all three devcontainer migration approaches (A, B, C) are wrong** for this project. The observability stack is sidecar infrastructure serving host-side AI agents, not a dev environment.

### Why devcontainer is wrong here

The devcontainer spec's `dockerComposeFile` + `runServices` requires designating a compose service AS the dev container via the `service` property. This couples the entire compose lifecycle to `devcontainer up/down`, which would:
1. Break host-side telemetry consumers (codex, gemini, claude CLIs)
2. Tie observability lifecycle to dev environment state
3. Require converting from image-based to compose-based devcontainer
4. Add complexity for secret handling (GRAFANA_PASSWORD)
