## Key Findings

**Layer 1 — Policy gap:** `no-warning-suppression.md` covers runtime suppression (filters, allowlists) but does NOT explicitly prohibit source-level suppression annotations (`# noqa`, `# type: ignore`, `// noinspection`). A new `.claude/rules/no-linter-suppression.md` is needed to close this.

**Layer 2 — Hook feasibility:** The existing `guard_install` and `guard_dotfile_edit` PreToolUse patterns are the right model. A new `guard_suppression` hook on `PreToolUse Write|Edit` can scan `new_string` content for suppression tokens before the edit lands. hk.pkl protection is feasible via regex step-name extraction and deny if any required step disappears. pyproject.toml protection on `[tool.ruff.lint.ignore]` additions is also feasible.

**Layer 2 — Existing violation in settings.json:** The inline PostToolUse formatter at line 58 of `.claude/settings.json` itself uses `2>/dev/null || true` — this violates the policy it indirectly enforces and should be migrated to a proper Python hook module (`format_on_save.py`).

**Layer 3 — Escalation protocol:** No documented protocol exists for agents stuck on linter errors. A new `.claude/rules/linter-escalation-protocol.md` should define the 7-step path: read error → search docs → check upstream → propose to human via AskUserQuestion → fix root cause → escalate if unfixable → document decision.

**Layer 4 — Validation extension:** `src/mde/validate/hk.py` currently only runs `hk validate` (Pkl syntax). It can be extended to parse step names with regex and compare against a `REQUIRED_STEPS` baseline (`ruff`, `ruff_format`, `shellcheck`, `typos`, `yamllint`, `mde-quality`), emitting `Severity.ERROR` for any missing step.
