**Key findings:**

1. **Custom sourceDir is supported and not an anti-pattern.** Chezmoi's `sourceDir` config key is the official mechanism for pointing to a non-standard location. Having the chezmoi source inside a Python package repo is valid.

2. **The `.chezmoi.toml.tmpl` self-reference is a bootstrap problem.** It writes `sourceDir = {{ .chezmoi.sourceDir | quote }}` - which on a fresh machine clone would record `~/.local/share/chezmoi` (the default clone location), not the `.chezmoisource/` subdirectory you intend. The custom layout only survives on machines where `chezmoi.toml` was manually configured first.

3. **`.zshrc` is unmanaged and drifting.** The direnv ghost warning is a symptom: direnv appended itself to `.zshrc`, but since `.zshrc` is not in `chezmoi managed`, this was invisible to the toolchain. `.gitconfig` and `.ssh/config` are also present but unmanaged.

4. **Doctor warnings are cosmetic but persistent.** The `suspicious-entries` warning (non-dotfile files in source dir) and `working-tree dirty` warning (Python package changes polluting chezmoi's git status check) will appear on every `chezmoi doctor` run. A `.chezmoiignore` could suppress the suspicious-entries warning.

5. **The Python package + dotfiles mixing works operationally** but creates two persistent friction points: the doctor warnings and the bootstrap gap on new machines.
