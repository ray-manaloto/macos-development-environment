## Claude Remember Plugin -- Complete Technical Reference

### Overview

**Repository:** `Digital-Process-Tools/claude-remember`
**Version:** 0.1.0
**License:** Source-available (use permitted; modification, redistribution, resale prohibited)
**Author:** Digital Process Tools ("Max")

A lifecycle-hook-based memory system for Claude Code. It hooks into session events, extracts conversation exchanges from JSONL session files, summarizes them via Haiku, and loads compressed memory back into context on the next session start.

---

### Architecture and Data Flow

```
PostToolUse (delta > 50 lines)
  -> save-session.sh <session-id>
    -> pipeline.shell extract (Python: parse JSONL -> human/assistant pairs)
    -> pipeline.shell build-prompt (Python: template substitution)
    -> claude -p --model haiku (sandboxed: cwd=/tmp, no tools, max-turns 1)
    -> pipeline.shell parse-haiku (Python: parse JSON response)
    -> append to now.md + save position to last-save.json
    -> NDC compression (hourly, background):
       now.md -> haiku -> today-YYYY-MM-DD.md (clears now.md)

SessionStart
  -> session-start-hook.sh
    -> inject memory files into context (stdout)
    -> recover most recent missed session (save-session.sh --force, background)
    -> trigger consolidation if past-day staging files exist (background):
       today-*.md -> haiku -> recent.md + archive.md

UserPromptSubmit
  -> user-prompt-hook.sh
    -> inject "[HH:MM TZ -- username]" timestamp
    -> warn if context >= 95%
```

### Memory File Hierarchy (5 layers, each compresses the one above)

| File | Scope | Update Frequency |
|---|---|---|
| `now.md` | Current session buffer | Every save (delta > 50 lines) |
| `today-YYYY-MM-DD.md` | Daily compressed summary | Hourly (NDC compression) |
| `recent.md` | Last ~7 days | On session start (consolidation) |
| `archive.md` | Older history | On session start (consolidation) |
| `remember.md` | Manual handoff note | User-triggered via `/remember` |

Additional files:
- `identity.md` -- agent identity/values (user-authored, lives in plugin dir)
- `core-memories.md` -- team-selected important moments
- `logs/memory-YYYY-MM-DD.log` -- pipeline logs
- `logs/autonomous/save-HHMMSS.log` -- background save logs
- `tmp/last-save.json` -- `{session: UUID, line: N}` for incremental extraction
- `tmp/last-save-ts` -- cooldown timestamp (epoch seconds)
- `tmp/save.lock` -- atomic lock file (noclobber)
- `tmp/last-ndc.ts` -- NDC cooldown timestamp
- `tmp/consolidation.lock` -- consolidation lock file

### CRITICAL FINDING: `data_dir` Is Documented But NOT Implemented

The `config.example.json` defines `data_dir` as configurable with default `.remember`. The README documents it. **However, none of the shell scripts actually read this value.** Every script hardcodes the data directory:

- **save-session.sh** (line ~35): `REMEMBER_DATA="${PROJECT_DIR}/.remember"` -- hardcoded, does NOT read `data_dir` from config
- **session-start-hook.sh**: All paths hardcoded as `$PROJECT/.remember/...`
- **post-tool-hook.sh**: Hardcoded `$PROJECT/.remember/tmp/...`
- **run-consolidation.sh**: Hardcoded `${PROJECT_DIR}/.remember`
- **log.sh**: `REMEMBER_LOG_DIR="${PROJECT_DIR:-.}/.remember/logs"`

The `config()` function in `log.sh` reads config.json with jq, but it is only used for:
- `.timezone` (used everywhere)
- `.cooldowns.save_seconds` (save-session.sh)
- `.cooldowns.ndc_seconds` (save-session.sh)
- `.thresholds.min_human_messages` (save-session.sh)
- `.thresholds.delta_lines_trigger` (post-tool-hook.sh)
- `.features.recovery` (session-start-hook.sh)

**`data_dir` is never read by `config()`.** The data directory is always `$PROJECT_DIR/.remember` regardless of configuration.

### Python Pipeline -- No data_dir Either

The Python code (`pipeline/`) does not reference `data_dir` or config.json at all. It receives paths as CLI arguments from the shell scripts. The `_last_save_path()` in `extract.py` hardcodes `.remember/tmp/last-save.json` relative to `project_dir`.

### Hook Registration

**hooks/hooks.json** (the plugin's hook manifest):
```json
{
  "hooks": {
    "SessionStart": [{"hooks": [{"type": "command", "command": "bash ${CLAUDE_PLUGIN_ROOT}/scripts/session-start-hook.sh"}]}],
    "PostToolUse": [{"hooks": [{"type": "command", "command": "bash ${CLAUDE_PLUGIN_ROOT}/scripts/post-tool-hook.sh"}]}]
  }
}
```

Notable: **UserPromptSubmit is NOT in hooks.json** -- the README instructs manual addition to `.claude/settings.json`. The plugin's hooks.json only registers SessionStart and PostToolUse.

### Path Resolution Logic

**PROJECT_DIR derivation** (the known bug):
- `save-session.sh`: `PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "$0")/../../.." && pwd)}"`
- `session-start-hook.sh`: `PROJECT="${CLAUDE_PROJECT_DIR:-.}"`
- `post-tool-hook.sh`: `PROJECT="${CLAUDE_PROJECT_DIR:-.}"`
- `run-consolidation.sh`: `PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "$0")/../../.." && pwd)}"`

The `dirname "$0"/../../..` fallback traverses 3 levels up from `scripts/` -- correct when installed as `.claude/remember/scripts/save-session.sh` but **broken for marketplace plugin installations** where `CLAUDE_PLUGIN_ROOT` points to the plugin cache directory, not the project tree. The fix (`CLAUDE_PROJECT_DIR` env var) is now applied in the first line of save-session.sh, so this bug is fixed upstream.

### PIPELINE_DIR / Config Resolution

- `PIPELINE_DIR="${CLAUDE_PLUGIN_ROOT:-${PROJECT_DIR}/.claude/remember}"`
- `REMEMBER_CONFIG="${PROJECT_DIR:-.}/.claude/remember/config.json"` (in log.sh)

Config is always read from the plugin installation directory, not the data directory.

### Session JSONL Location

Sessions are stored at: `~/.claude/projects/<project-path-slug>/*.jsonl`

Where `<project-path-slug>` = project path with `/` replaced by `-` (e.g., `-Users-foo-myproject`).

### Locking Mechanism

Uses bash `noclobber` for atomic lock acquisition:
```bash
if ! ( set -o noclobber; echo $$ > "$LOCK_FILE" ) 2>/dev/null; then
    # check if PID is alive, take over if stale
fi
```

### Dispatch / Extension System

`log.sh` provides a `dispatch()` function that runs executables from `hooks.d/<event>/`:

Lifecycle events dispatched:
- `before_save`, `after_save` (save-session.sh)
- `before_session_start`, `after_session_start` (session-start-hook.sh)
- `after_user_prompt` (user-prompt-hook.sh)
- `before_consolidate`, `after_consolidate` (run-consolidation.sh)
- `after_post_tool` (post-tool-hook.sh)

### Haiku Invocation (Sandboxed)

cd /tmp && env -u CLAUDECODE claude -p \
    --model haiku --allowedTools "" --max-turns 1 \
    --output-format json \

Key sandboxing: `cwd=/tmp`, no tools, no MCP servers, `CLAUDECODE` env stripped to allow nesting.

### Cost

Haiku pricing: $0.80/M input, $4.00/M output, $0.08/M cache-read. Typical save costs < $0.01. Daily usage: a few cents.

### Design Philosophy (from blog post)

- Solves memory "from the inside" -- designed by an agent that experiences the reset problem
- Compressed, practical memory over perfect recall
- Layered compression: raw -> one-line summaries -> weekly paragraphs
- Identity files (`identity.md`, `core-memories.md`) provide stable context
- Handoff note (`remember.md`) is consumed once (cleared after reading)
- Auto-compact should be DISABLED -- it discards conversation before the save pipeline can capture it

### Known Limitations

1. **`data_dir` not implemented** -- config key exists but all scripts hardcode `.remember`
2. **UserPromptSubmit not in hooks.json** -- must be manually added to settings.json
3. **No CHANGELOG or releases** -- repository has no version history beyond initial commit
4. **Requires Anthropic API access** -- Haiku calls go through the `claude` CLI
5. **Shell-heavy architecture** -- bash scripts handle locks, cooldowns, file I/O; Python handles parsing/prompts
6. **No PreCompact or Stop hooks** -- memory can be lost if auto-compact fires or session ends without `/remember`
7. **Context percentage** -- reads from `/tmp/claude-ctx-pct` file which must be populated externally

### Implications for Custom data_dir (e.g., `.generated/remember/`)

To redirect the data directory, you would need to either:

1. **Symlink approach** (current MDE strategy): `ln -s .generated/remember .remember` -- works because all scripts resolve `.remember` relative to `PROJECT_DIR`
2. **Patch all scripts** -- replace every `$PROJECT/.remember` and `${PROJECT_DIR}/.remember` with a config-read value. This requires modifying 4 shell scripts (save-session.sh, session-start-hook.sh, post-tool-hook.sh, run-consolidation.sh) plus log.sh, plus `extract.py` in the Python pipeline.

The symlink approach is the least invasive and works correctly with the current codebase.
