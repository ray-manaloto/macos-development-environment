## Issue 1: Rekor Public Key Parse Error -- BENIGN

**Root cause**: Known bug in sigstore-rs (issue [sigstore/sigstore-rs#508](https://github.com/sigstore/sigstore-rs/issues/508)). The Sigstore TUF trust root contains two Rekor keys -- a current ECDSA P256 key and an older Ed25519 key. The library hardcodes ECDSA P256 as the signing scheme, so it parses the newer key fine but fails on the older Ed25519 key, producing the warning.

**Security impact**: None. Attestation verification succeeds using the valid ECDSA P256 key. Both atuin and uv report "GitHub artifact attestations verified" immediately after the warning (log lines 115, 124).

**Fix status**: PR [sigstore/sigstore-rs#551](https://github.com/sigstore/sigstore-rs/pull/551) was merged 2026-03-11, but the latest sigstore-rs release remains v0.13.0 (2025-10-16). Mise uses sigstore 0.13.0. The fix will propagate once sigstore-rs cuts a new release and mise updates its dependency.

**Action**: No issue to file (jdx/mise has issues disabled). No mde validate flag needed. This is upstream noise that will resolve itself.

## Issue 2: 1Password Shim Race During Update -- REAL BUT TRANSIENT

**Root cause**: A timing/ordering issue during `mde update`. When `mise upgrade` replaces 1password-cli and `mise prune` removes the old version, the shim at `~/.local/share/mise/shims/op` can be in a transitional state. When `chezmoi doctor` (called during `validate_all`) invokes `op --version`, the shim triggers a mise auto-install, outputting installation text instead of a version number.

**Current state**: Works fine now. `~/.local/share/mise/shims/op --version` returns `2.33.0` and `chezmoi doctor` reports `ok 1password-command`.

**The update step order is already correct** (mise upgrade -> mise lock -> mise reshim -> mise install -> mise prune -> chezmoi apply -> validate_all). The error happened because during the specific update run, the tool was in a transitional state between prune and the validation step.

**Recommended fix**: The cleanest approach is to ensure `mise reshim` runs after `mise prune` (currently reshim runs BEFORE prune). Changing the order to: upgrade -> lock -> install -> prune -> reshim -> chezmoi apply -> validate would guarantee shims point to installed versions before validation runs.
