## Architecture Review: chezmoi-toolkit and mise-toolkit

### 1. Consistency Between Plugins

**Directory layout** — Both plugins follow the same structure: `.claude-plugin/plugin.json`, `agents/`, `hooks/hooks.json`, `hooks/scripts/`, `skills/<name>/SKILL.md`, `skills/<name>/references/`. This is consistent and correct.

**plugin.json fields** — Both have identical field sets: `name`, `version`, `minVersion`, `description`, `author`, `repository`, `license`, `keywords`. No missing or extra fields. Versions match marketplace.json entries exactly.

**Agent frontmatter** — Here the plugins diverge in two ways.

WARNING — `chezmoi-workflows` and `mise-tasks` carry an `allowed-tools:` frontmatter key that the agent definitions do not use. The canonical agent model in Claude Code uses `tools:` (as seen in both agent files). An `allowed-tools:` field on a *skill* file has no documented meaning in the plugin spec — it looks like a copy/paste from an older agent format and will silently be ignored at runtime.

Affected files:
- `/rsm-subagents/plugins/chezmoi-toolkit/skills/chezmoi-workflows/SKILL.md` line 5: `allowed-tools: Read, Edit, Bash`
- `/rsm-subagents/plugins/mise-toolkit/skills/mise-tasks/SKILL.md` line 4: `allowed-tools: Read, Bash, Glob, Grep, Edit, Write`

INFO — `color:` is present on both agent files (`yellow` for chezmoi-specialist, `cyan` for mise-specialist). No inconsistency.

INFO — `model: inherit` is used consistently on both agents.

**Hook structure** — chezmoi-toolkit registers both `PreToolUse` and `PostToolUse` hooks. mise-toolkit registers only `PreToolUse`. This is intentionally asymmetric (the mise guard only needs to intercept, not remind), and the structure follows the same schema. No issue.

**Skill naming conventions** — chezmoi skills use `chezmoi-<topic>` and mise skills use `mise-<topic>`. Both are lowercase-hyphenated and plugin-prefixed. Consistent.

**Skill description style** — There is an inconsistency in style:

WARNING — chezmoi skills use mixed description styles:
- `chezmoi-config`: one long prose sentence, no triggers listed explicitly
- `chezmoi-workflows`: short two-clause sentence with explicit "TRIGGERS -" token
- `chezmoi-troubleshooting`, `chezmoi-migration`, `chezmoi-advanced-config`, `chezmoi-agent-config`: medium-length prose with "Use when" examples

Mise skills are uniformly formatted as multi-line `>` blocks opening with "This skill should be used when the user asks to..." followed by explicit quoted phrases. This is superior for model triggering because literal quoted user phrases are more discriminating than topic nouns.

The `chezmoi-workflows` description is the weakest in the set. It reads: *"Dotfile backup and sync with chezmoi. TRIGGERS - chezmoi, dotfiles, sync dotfiles, backup configs, cross-machine sync."* The word "chezmoi" alone will trigger it for almost any chezmoi question, making it over-broad and potentially stealing invocations from the more specific skills.

### 2. Skill Coverage Completeness

**Overlapping content:**

The workflows skill includes a full table of doctor fields (lines 270-279); the troubleshooting skill repeats a nearly identical table (lines 26-36). This is the only meaningful content overlap, but it means a fix or new doctor field must be updated in two places.

**Triggering width — too vague or too narrow:**

CRITICAL — `chezmoi-config` has no explicit trigger phrases at all. Its description is a single 118-word sentence covering every possible chezmoi feature. A model routing between six chezmoi skills will find it hard to prefer `chezmoi-config` over `chezmoi-workflows` or `chezmoi-advanced-config` when a user asks "how do I add a template?". The lack of explicit trigger tokens is the single highest-risk gap for mis-routing.

WARNING — `mise-enforcement`'s description explicitly names `brew install`, `npm -g`, `pipx install`, `cargo install`, `go install` as triggers. The guard-install.sh hook also blocks `bun add -g`, `bun install -g`, `pip install --user`, and `gem install`. These four patterns appear in the hook but not in the skill description, creating a gap where the hook fires but the agent has no skill context loaded to explain the policy.

Affected file: `/rsm-subagents/plugins/mise-toolkit/skills/mise-enforcement/SKILL.md` line 7 — missing `bun add -g`, `bun install -g`, `pip install --user`, `gem install` in the trigger description.
