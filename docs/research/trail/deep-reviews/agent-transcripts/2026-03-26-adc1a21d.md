## Answer

Yes, you can create a `PostToolUse` hook that triggers after `Edit`/`Write` operations with path matching. Here's how:

### 1. PostToolUse with File Edits - Yes, this exists

The `PostToolUse` event fires after successful tool execution. You can match it on the `Edit|Write` tools using the `matcher` field:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "uv run mde-py validate --plugins"
          }
        ]
      }
    ]
  }
}
```

### 2. Path Pattern Matching - Limited but possible

The documented `matcher` field **does NOT directly support path patterns** like `"rsm-subagents/**"`. Matchers work on:
- **Tool names** (PreToolUse, PostToolUse): `Bash|Edit|Write`, `mcp__github__.*`
- **Event metadata** (not file paths): session start reason, notification type, etc.

However, you can **extract the file path in your hook command** and check it:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "FILE_PATH=$(jq -r '.tool_input.file_path' | cat); if [[ \"$FILE_PATH\" == *\"rsm-subagents\"* ]]; then uv run mde-py validate --plugins; fi"
          }
        ]
      }
    ]
  }
}
```

Or better, use a separate shell script:

```bash
#!/bin/bash
# .claude/hooks/validate-on-rsm-edit.sh
FILE_PATH=$(cat | jq -r '.tool_input.file_path // empty')

if [[ "$FILE_PATH" == *"rsm-subagents"* ]]; then
  cd /Users/rmanaloto/dev/github/ray-manaloto/macos-development-environment
  uv run mde-py validate --plugins
  exit $?
fi

exit 0
```

Then in settings.json:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/validate-on-rsm-edit.sh"
          }
        ]
      }
    ]
  }
}
```

### 3. settings.json Format

Use **`.claude/settings.json`** (project-level, shareable) or **`~/.claude/settings.json`** (global):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "path/to/script.sh"
          }
        ]
      }
    ]
  }
}
```

**Key config notes:**
- `matcher` is a regex (case-sensitive): `Edit|Write` matches either tool
- `type: "command"` for shell scripts
- Use `"$CLAUDE_PROJECT_DIR"` for relative paths
- Exit code 0 = success, 2 = block the action (you don't need blocking here)

### 4. Running Your Validation Command

Yes, the command can be `uv run mde-py validate --plugins`. Your hook input receives this on stdin:

```json
{
  "session_id": "...",
  "cwd": "...",
  "hook_event_name": "PostToolUse",
  "tool_name": "Edit",
  "tool_input": {
    "file_path": "/path/to/file",
    "new_contents": "..."
  }
}
```

Extract the file path with `jq -r '.tool_input.file_path'` and gate your validation.

### Full Example for Your Use Case

**.claude/settings.json:**
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/validate-rsm-plugins.sh"
          }
        ]
      }
    ]
  }
}
```

**.claude/hooks/validate-rsm-plugins.sh:**
```bash
#!/bin/bash
set -e

FILE_PATH=$(cat | jq -r '.tool_input.file_path // empty')

# Only run validation if a file in rsm-subagents/ was modified
if [[ -z "$FILE_PATH" || "$FILE_PATH" != *"rsm-subagents"* ]]; then
  exit 0
fi

echo "Running plugin validation for $FILE_PATH..." >&2
cd "$CLAUDE_PROJECT_DIR"
uv run mde-py validate --plugins
```

Then make it executable:
```bash
chmod +x .claude/hooks/validate-rsm-plugins.sh
```
