### Findings

#### P1 CRITICAL: No Homebrew bootstrap -- fresh machine `chezmoi init --apply` will fail silently

**File:** `.chezmoisource/.chezmoiscripts/run_onchange_before_install-packages-darwin.sh.tmpl`, lines 6-8

```bash
if ! command -v brew >/dev/null 2>&1; then
  echo "brew not found; skipping Brewfile install" >&2
  exit 0
fi
```

On a fresh Mac, Homebrew itself is not installed. There is no `run_once` or `run_before` script that installs Homebrew. The `before_install-packages-darwin` script silently skips the entire Brewfile (exit 0) if `brew` is missing. This means:
- llvm and lld never get installed
- mise config.toml sets `CC=/opt/homebrew/opt/llvm/bin/clang` which does not exist
- Any `mise` operation that evaluates `[env]` will export broken CC/CXX paths
- Builds will either fail (CC not found) or silently fall back to Apple clang, defeating the whole purpose

**Recommendation:** Add a `run_once_before_install-homebrew.sh.tmpl` that installs Homebrew via the official installer, or at minimum change the skip to `exit 1` so the failure is visible.

#### P2 IMPORTANT: Duplicate/conflicting CC/CXX configuration between mise and zsh

**Files:**
- `.chezmoisource/dot_config/mise/config.toml.tmpl`, lines 29-30: `CC = "/opt/homebrew/opt/llvm/bin/clang"` (absolute path)
- `.chezmoisource/dot_oh-my-zsh/custom/llvm.zsh`, lines 21-22: `export CC=clang` / `export CXX=clang++` (bare names relying on PATH)

The mise config sets CC to an absolute path. Then `llvm.zsh` (sourced later during interactive shell init) overwrites CC/CXX with bare `clang`/`clang++`. In an interactive shell where both mise and oh-my-zsh are active, the final CC/CXX will be `clang`/`clang++` (the bare names), NOT the absolute paths mise set. Whether this resolves to brew or Apple clang depends on PATH order at that moment.

More critically, in non-interactive contexts (build scripts, mise tasks, CI), only the mise env vars apply, giving the absolute path. This creates an inconsistency where interactive and non-interactive shells may use different compilers.

**Recommendation:** Remove the CC/CXX exports from `llvm.zsh` entirely. The mise config already handles PATH, CC, CXX, LDFLAGS, and CPPFLAGS. The `llvm.zsh` file's PATH prepend is also redundant with mise's `_.path`. If `llvm.zsh` must exist for opt-out (`MDE_USE_LLVM=0`), it should only set `PKG_CONFIG_PATH` (which mise does not set) and skip everything else.

#### P2 IMPORTANT: Mise `_.path` and env vars evaluate even when llvm is not installed

**File:** `.chezmoisource/dot_config/mise/config.toml.tmpl`, lines 28-32

The mise `[env]` block is unconditional (within darwin). Mise evaluates these on every shell activation. If llvm is not yet installed (e.g., brew bundle hasn't run, or brew installed but llvm formula failed):
- `CC=/opt/homebrew/opt/llvm/bin/clang` points to a nonexistent binary
- `_.path` prepends a nonexistent directory (harmless but confusing)
- Any tool or build system reading CC will get a hard failure with a misleading "file not found" error

Mise has no conditional `[env]` mechanism, so this is a design limitation. However, there is no validation check that catches this.

**Recommendation:** Add a validation check in `src/mde/validate/brew.py` (or a new `validate/llvm.py`) that verifies `/opt/homebrew/opt/llvm/bin/clang` actually exists and reports its version. This catches the case where the Brewfile ran but llvm installation failed.

#### P2 IMPORTANT: No validation that `clang --version` reports brew LLVM, not Apple clang

**File:** `src/mde/validate/brew.py`

The brew validation checks that `llvm` and `lld` are in the installed formulae set, but does not verify that the active `clang` binary is actually the brew one. Given the PATH ordering complexity (mise shims, oh-my-zsh, system), it is entirely possible for `which clang` to resolve to `/usr/bin/clang` (Apple clang) even when brew llvm is installed.

**Recommendation:** Add a check that runs `clang --version` and verifies the output contains `Homebrew` or a version number matching `brew info llvm --json | jq '.[0].versions.stable'`, rather than `Apple clang version`.

#### P2 IMPORTANT: Chezmoi script ordering -- mise install runs AFTER brew bundle, but with a race

**Files:**
- `run_onchange_before_install-packages-darwin.sh.tmpl` -- runs brew bundle
- `run_onchange_after_install_mise.sh.tmpl` -- runs mise install

The `before` script runs brew bundle (which installs llvm), and the `after` script runs mise install. The naming (`before` vs `after`) suggests correct ordering relative to file application. However, the `before` script runs before chezmoi applies `~/.config/mise/config.toml`, and the `after` script runs after. This means:

1. `before` script: brew installs llvm -- good
2. chezmoi applies `~/.config/mise/config.toml` with CC/CXX env vars
3. `after` script: `mise install --yes` runs, which evaluates the config including CC/CXX

This ordering is correct. No bug here, but worth noting that if someone adds a `run_before` mise step, the config won't exist yet.
